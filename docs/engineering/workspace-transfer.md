# Workspace ↔ VM transfer fixture (experimental)

The protocol and quota history below describes the synthetic fixture. The installed-run final file boundaries and product-facing session are specified in [Workspace final effects](workspace-final-effects.md).

## Scope and authority

This is a working **transport + WorkspaceStore synthetic-fixture** increment, not an Agent, App consent flow, model/MCP bridge, or shared-business-output authorization gate. `Tools/WorkspaceTransfer/main.swift` is a separate trusted test executable. It can only create its baked synthetic source and publish a new `export` directory inside its caller-selected private test session. It has no arbitrary source-selection, overwrite, credential, URL, shell, or production-fallback option. The internal WorkspaceStore seams are not public App APIs. No F03 lock, authority ledger, or transferable permit is introduced.

The signed native host imports the synthetic source with the existing WorkspaceStore; captures its private regular-file copy; boots the real Linux VM without NICs or directory shares; transfers it; receives the guest's edited and tested complete result; waits for actual stopped state and settled VZ callbacks; then explicitly reviews and exports the result with WorkspaceStore. The fixture checks original preservation, exported exact bytes, guest failing-then-passing Python tests, and stale-review rejection after deliberately mutating the host-owned reviewed fixture. Nothing imported or edited is executed on macOS.

## Protocol and ownership

A distinct **port 4062**, `workspace-fixture-v1` image profile, and one queue-owned transfer state are bound to the actual accepted `VZVirtioSocketDevice` and listener objects. No message identifier selects host context. Runtime control 4060 and diagnostic 4050/4051 stay separate; profiles cannot be combined. There is one connection, no reconnect/resume, and no generic IP service.

Frames are 4-byte big-endian lengths plus strict UTF-8 JSON, at most 16,384 bytes. Native ingress uses the raw RuntimeJSON grammar before Foundation conversion: decoded duplicate keys, Boolean/decimal/exponent integer substitutions, malformed schema, unknown fields, and excessive nesting/nodes fail closed. The receive buffer is 16,388 bytes, output queue 32,768 bytes, and each socket turn reads at most 4,096 bytes. The host sends one acknowledged frame at a time. The result channel has 8,192 frames per tree; host total incoming frames are capped at 16,400, including acknowledgments. Existing 65-second run/10-second stop deadlines and the runtime resource configuration remain unchanged.

Tree messages are `begin(count,total)`, sequential `file(path,size,sha256)`, `chunk(offset,data)`, `end`, and `complete(sha256)`, each carrying exact integer `v=1` and monotonic `seq`. Chunks contain at most 4,096 decoded bytes; canonical base64, exact offsets, exact final file sizes, SHA256 and complete-tree SHA256 are validated. Tree SHA256 hashes sorted records `UTF8(path) + NUL + ASCII(size) + NUL + ASCII(file SHA256) + LF`. File paths are relative, already NFC, and bounded to 1,024 UTF-8 bytes, 255 bytes/component and 16 components. Existing exclusions apply to every component. Inferred directories count toward the 1,000-entry bound; files are at most 4 MiB and total contents at most 16 MiB. Links, devices, metadata, permissions and special entry types have no wire representation. Empty directories are explicitly unsupported and rejected on outbound capture, not silently lost.

Malformed frames, framing overflow, hash/size/count mismatch, replay, disconnection or stop poison the session; partial data cannot produce a snapshot. Incoming file bytes first reside in **private bounded, session-owned memory quarantine**. Complete validation produces a Swift value snapshot (copy-on-write Data values), not a guest path or a chmod-based immutability claim. Later chunks cannot mutate that captured value. After VM shutdown, WorkspaceStore independently validates the frozen tree, materializes it in an exclusively created host `quarantine-*` directory using its existing descriptor/no-follow/ACL/xattr rules, rescans it, and only then replaces the snapshot's working handle. Failed partial disk materializations never become reviewable. Existing foreign/stale-review checks and exclusive new-directory export remain in force. The original baseline and source binding are retained.

Guest materialization is confined to new `/work/transfer`, on the fresh 64 MiB private disk. The fixed guest-only script runs the transferred synthetic Python test, observes failure, changes subtraction to addition, reruns the test, captures the complete regular-file result and supplies a digest-bound test receipt. That receipt is fixture evidence, not a general attestation that an arbitrary malicious guest genuinely ran tests. No guest-owned path reaches host filesystem APIs, and no tar is received or extracted.

## Reproduce

Use new private artifact/session directories outside the repository; keep image inputs and their ancestry non-mutating throughout the run. Reuse the already pinned offline runtime package cache and diagnostic bundle. No vendor CLI is needed.

```sh
swift run WorkspaceTransferChecks
swift run WorkspaceChecks
python3 Tools/AgentRuntime/build.py "$CACHE" "$DIAGNOSTIC_BUNDLE" "$ART/workspace-image" --workspace
python3 Tools/WorkspaceTransfer/build_host.py fixture "$ART/workspace-host"
codesign --force --sign - --entitlements scripts/vm-probe.entitlements "$ART/workspace-host/host"
python3 Tools/WorkspaceTransfer/verify_vm.py "$ART/workspace-host/host" "$ART/workspace-image" "$ART/workspace-runs"
```

The verifier runs normal → cancel after the first received 4,096 bytes → fresh normal, then three additional owned VMs with SIGTERM delivered at explicit post-VM, pre-rename and post-rename barriers. It checks no precommit export, preserved committed bytes after cancellation, distinct session disks, settled callbacks before console release, and equal normal/fresh exported tree hashes. Protocol logs contain static events, counts, hashes and Boolean outcomes only; no file contents, paths or raw guest console are logged in this profile. Artifacts contain synthetic fixture bytes and remain private.

## Host limits and workflow commit

The receiving store preflights the complete frozen tree, including inferred directories, before building WorkspaceNodes, reserving disk capacity, or creating quarantine. It no longer serializes and decodes the result merely to validate it. Store limits are intersected with channel hard limits; `transferFlow` supplies those same effective limits to ingress. Channel declarations cannot increase them. Workspace depth counts directories (a root file has depth zero); the channel additionally retains its 16-component maximum.

The receiver charges the full declared file capacity before allocating its fixed-size buffer. Each chunk checks bounded canonical base64 length and declared/effective remaining bytes before decoding; the final fence copies at most 4,096 bytes into that already allocated buffer. The synchronized budget uses subtraction (`new <= capacity - used - reserved`), survives across frozen value lifetimes, and releases on poisoned/cancelled receivers or last frozen-value release. Stores/channels in one budget domain must share the host-owned budget instance. The fixture does so for its receiving flow. No guest identifier chooses a budget.

Quarantine and export reserve the entire preflighted payload before creating their root; every actual write is at most 4,096 bytes and rechecks file/aggregate bounds. Counters distinguish cumulative bytes actually accepted/written, current used/reserved, committed bytes, actual-used peak, reservation-inclusive peak, released reservations, and orphaned bytes. Adoption and successful rename end the legacy **temporary** store/run accounting; the new task domain described below instead moves actual bytes to committed and keeps them charged. Cancellation/failure rolls back only retained identities of exclusively created nodes, never recursively deleting unknown/replaced nodes. Failed cleanup leaves capacity charged as orphaned rather than pretending recovery. Physical allocator overhead, base64/JSON buffers, retained raw Data copies outside the frozen wrapper, outbound message arrays and baseline/review scan copies remain outside payload accounting. No process RSS or VM-total bound is claimed.

VM completion leaves signal cancellation installed through host receive/review/export. `WorkspaceExportCancellation` is a narrow host filesystem action fence, **not** a replacement run lifecycle, grant or approval framework. Its host-only owner and irreversible workflow generation are distinct from F03's run epoch/generation. Cancellation never resets. Concrete bounded writes, payload append and exclusive rename use the same mutex as `cancel()`: cancellation linearized first prevents that effect; rename first returns committed success, or `committedUnverified` if post-commit verification fails. Neither case deletes published user files. OS signal delivery itself is asynchronous; the cancellation linearization is the host handler's latch, not the kernel signal-send timestamp. Legacy Boolean cancellation callbacks are latched when observed, but callers needing ordered cancellation must call the shared action cancellation object.

A separately approved `exportReviewedAfterStop` uses a fresh host action cancellation and an existing immutable review. It still checks source/working/destination identity and stale/foreign reviews, and does not clear or reuse the old workflow cancellation. This trusted-host API is not UI approval or shared-run authority. The installed-grant quota intersection below supplies accounting; `WorkspaceRunSession` binds the product flow to the shared lifecycle as described in [Workspace final effects](workspace-final-effects.md).

### Installed-grant quota binding

`WorkspaceGrantQuota.authenticated` calls the **actual** F03 `validateAttachment(handle:grant:)` with an installed opaque handle and the immutable host grant. A decoded grant or echoed digest alone cannot construct the binding. `WorkspaceStore.bindTransferQuota` matches that grant's UUID to the store-owned snapshot ID; guest frames never select a snapshot or quota domain. Rebinding a snapshot to another run is rejected. Once bound, the legacy unbound flow and unbound frozen-result fallback are rejected.

The actual store → flow → receiver → frozen-result → quarantine/export-materializer path intersects product, installed run, store, and channel ceilings. UInt64 memory/disk values are clamped before conversion to Int. Both payload and temporary disk reservations debit the store domain **and** the shared installed-handle domain before growth or writes; failed multi-domain reservation rolls back only acquired reservations. Repeated authentication of the same handle returns the same counters, not a fresh pool. Frozen wrappers retain payload charges; unknown disk replacements retain orphan charges. The bounded process-local registry holds at most 256 installed identities, never evicts or resets charged entries, and fails closed when full. A reviewed retirement/reclamation policy is required before production use.

The message ceiling is also applied before raw body admission, receiver JSON parsing, and flow handshake parsing. The native receive-buffer/read size uses the selected host context's ceiling, and rejects an excessive four-byte header without waiting for its body. Existing 4060 and diagnostic limits are unchanged.

**Scope is conservative subdomain ceilings, not free capacity or execution permission.** ResourceLimits still has no separate task quota field. The R3 task policy below is a NEW concrete host-owned type, not a retroactive claim about RunGrant. CPU/concurrent-request values are not repurposed as workspace channel approval. VM hardware allocations, raw disk reservation, global allocator/RSS, JSON/base64/transient decode storage, outbound message arrays, baseline/review scans and escaped raw Data remain outside these counters. VM and host usage are not summed against one whole-run allocator. Memory/disk grant ceilings constrain the measured workspace subdomain but do not authorize spending the rest of a VM resource budget on the host.

The fixture driver installs its own explicitly synthetic grant with the real imported snapshot ID, no connection grants, and unchanged VM hardware ceilings. This is not file-access approval or a production fallback. Quota authentication is a metadata-binding check, not a lock across later IO; concrete writes, renames and socket effects require their corresponding shared-lifecycle boundaries.

Native tests retain the original 57 cases and add real-installed-handle quota checks. Behavioral REDs witnessed a two-byte installed grant accepting three payload bytes and a 128-byte message grant retaining a 129-byte header. The other expanded binding, exact-boundary, simultaneous-flow, retention, cancellation, orphan, and materialization defenses first ran GREEN; they are not relabeled as independently witnessed REDs. The new SwiftPM membership is limited to the concrete WorkspaceTransferChecks executable. The standalone build helper compiles the existing real Host/Contracts implementation with package access enabled; it neither stubs shared authority nor executes any received project content.

### Authoritative host task quota and workflow binding (R3 candidate)

After installing the real run and matching its snapshot, the trusted fixture calls `WorkspaceStore.createTransferTask(for:limits:)` **before any transfer instance is created**. `WorkspaceTaskLimits` is immutable input captured at that host task-creation boundary. It specifies retained payload, current-plus-committed disk, cumulative accepted input, per-file, entry, depth, path and message ceilings. No guest task ID, decoded grant field, callback, clock provider or execution permit creates the domain. Repeating creation with identical owner/limits returns the same `TaskQuotaLedger`; changed limits, foreign store ownership and first creation after transfer has begun are rejected.

The ledger is retained by the existing installed-handle registry and shared across files, accepted channels, replacement transfer objects and synthetic reconnects. The VM fixture itself still supports one socket per VM: native reconnect tests exercise replacement flow objects, not a newly implemented vsock resume protocol. The effective ceiling intersects product, actual run, host task, workspace and channel. UInt64 ceilings are clamped before Int conversion. Reservations debit all three payload/disk domains before decode/growth or staging creation. Cumulative input uses `amount <= limit - accepted - reserved`; close/error releases live payload but never accepted input. A bad base64 decode refunds unaccepted reservation, while a later digest error does not erase already accepted bytes.

Task disk capacity counts `used + reserved + committed`; orphaned bytes remain included in used. Successful adoption/rename transfers actual bytes to committed without releasing task headroom. The actual-used peak includes committed trees; reservation-inclusive peak additionally includes in-flight capacity. The entire preflighted disk reservation is settled once on short write, error or cancellation. A real child-process RLIMIT_FSIZE probe writes 4097 of 8192 reserved bytes, observes EFBIG, verifies exact cleanup/release, and then reuses capacity for adoption/export. Separate task lifetime attempt limits (host-selectable downward, product maximum 64 transfer instances and 64 materializations) also bound zero-byte trees, flow objects and directory metadata; failure/close/reconnect never refunds these lifetime attempts. Committed and orphaned task charges are deliberately not reclaimed: no retirement API can forget files or unfinished cleanup. The existing 256-identity registry remains fail-closed and is not enlarged or evicted.

Each transfer captures a trusted workflow owner/generation; cancellation refuses already-created receivers and outbound flow progress. Sealed values retain both task provenance and their payload charge. Quota metadata alone cannot manufacture a task-owned result. Review captures the exact immutable tree, digest and task reference only after host materialization; a review predating task creation is stale. Export carries the immutable digest, retained destination-parent descriptor, exclusive stage and new basename to the cancellation-ordered rename. The ordinary workflow stays cancelled after VM completion or run Stop. A separate explicitly approved postStop export uses a fresh action cancellation, the same immutable review and the same task disk ledger; it neither resets input nor reactivates old receivers/run authority.

Six behavioral REDs were witnessed in this increment: cancelled precreated receiver accepted bytes; adopted disk was uncharged; cancellation between validation and write still wrote two bytes; pre-task review published; quota-only synthetic frozen value materialized; zero-byte transfers/exports bypassed lifetime bounds. The first task-API check was a missing-symbol compile RED, not a behavioral RED. Expanded exact-boundary/concurrency/frozen/error/orphan/real-shortwrite and commit-order cases first ran GREEN. All original 72 names remain. The signed fixture now selects explicit task limits and emits checked task metrics for six VM session modes.

#### Task-depth export regression repair

Export preflight checks the task-effective directory depth of every immutable reviewed node before constructing `WorkspaceDiskWrite` or creating the staging directory. It uses scanner semantics: the root is depth zero, a file basename adds no directory depth, and an empty directory leaf counts in full. This covers trees imported before task binding and working trees changed and reviewed after task creation, for both ordinary and separately approved postStop exports. Other quota, review, cancellation and publication rules are unchanged.

The permanent native matrix adds 24 named below/exact/above cases to the existing 92. Before repair, all eight above-depth rows actually published: file rows wrote two bytes and empty-directory rows reached rename. Below/exact controls already passed. After repair, above-depth rows require `WorkspaceError.rejected("depth limit")`, unchanged disk/reservation counters, no write/rename observations, and an unconsumed materialization attempt. That attempt observation plus the source ordering establishes rejection before staging; absence of a surviving stage alone is not a mkdir trace. Positive rows compare exact exported bytes/paths, preserve cumulative input and task identity, and enforce independent postStop cancellation without reviving the old workflow. The initial matrix placement after the deliberate registry-exhaustion check was a harness failure, not a depth RED; the matrix now runs before that terminal exhaustion check.

**Shared-lifecycle file-effect contract.** Concrete workspace write/rename effects acquire writer and workflow ownership first, then lifecycle, sample the reviewed clock after all application-lock waits, validate installed handle/epoch/connection/task binding, and invoke one bounded syscall. Stop detaches under lifecycle and cancels workflow after unlock; a lifecycle-to-workflow reverse lock edge is prohibited. Prepare hashes, paths, credentials and observations outside the final fence. Partial/EINTR/EAGAIN retries require a new final lifecycle entry. No generic closure, queued effect, transferable permit or second RunLifecycle is acceptable. See [Workspace final effects](workspace-final-effects.md) for the concrete implementation.

## Evidence boundaries and remaining work

Native tests exercise the actual Swift framed ingress, malformed JSON/numbers, path exclusions/traversal/NFC/collisions, forbidden types, order/replay, byte/digest/count bounds, stop poisoning, frozen late-frame isolation, explicit empty-directory rejection, and a 1,000-file/16 MiB boundary tree. WorkspaceChecks is a separate filesystem regression suite. Native max-bound acceptance is not a full-sized VM throughput test; the real VM fixture is small and deterministic.

The first interface test was a missing-symbol compile RED; behavioral REDs were independently observed for native overflow poisoning, missing builder profile, silently omitted empty directories, and too-small frame budget. Other negative vectors first ran GREEN; do not describe every vector as independently witnessed RED.

The fixture uses a fixed project and guest test script. Its protocol does not support empty-directory transport or vsock reconnect/resume. Its checks do not cover arbitrary guest test attestation, maximum-size VM deadline performance, adverse fsync failure injection, a hostile same-UID/root writer, or guest process/resource isolation beyond the fixed fixture. Partial in-memory quarantine is not a persisted crash-recoverable transfer journal. Native approval and shared-run consumer interfaces belong to the application session described in [Workspace final effects](workspace-final-effects.md).
