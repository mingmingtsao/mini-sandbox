# 桌面级安全沙箱：产品设计评审

## 结论

授权边界、秘密模型、首版范围和运行状态机存在不一致，建议明确下列待决事项后再冻结对应实现规格。

评审覆盖产品定位、模块、接口、界面与原型的一致性和可验收性，基于文档与静态源码，不代表实现验证。以下建议均待确认；阻塞项针对各自对应的里程碑。

## 需要先确认的问题

### R01 · 未批准的低风险能力可以静默放行，与授权红线冲突

**影响阶段：所有带权限执行的版本；应在实现前统一。**

- **证据：**M5 的输入是“未经批准”的能力，但低风险默认“静默允许并记录”；全局不变式又规定 M4 不得执行未经 M3 批准的能力，接口保留了 `silent-allow-low-risk`。[02，L479–491](source/02-模块设计.md?plain=1#L479-L491) [02，L687–694](source/02-模块设计.md?plain=1#L687-L694) [03，L398–425](source/03-接口契约.md?plain=1#L398-L425)
- **影响：**例如进程派生被归为低风险，用户主动取消后是否仍可能放行，不能由当前规格得到唯一答案。[02，L300–304](source/02-模块设计.md?plain=1#L300-L304)
- **建议决策：**明确区分“事前已批准的基础能力”“未申请能力”“显式拒绝能力”。后两者不能仅因低风险而自动扩权；如保留基础白名单，必须在运行前可见并进入授权快照。
- **建议验收：**取消进程派生后尝试启动子进程，被拒绝且留证；补授在新的有效批准产生前不得生效。

### R02 · 引用模型与“秘密不进 guest”的总承诺冲突，且兼容接入契约未完成

**影响阶段：M2 与自定义服务支持前。**

- **证据：**引用模型明确把数据库连接串、SSH 私钥等注入 guest 进程内存，也承认进程主动 dump 的残余风险；另一处否决条件却禁止 guest 持有可访问宿主/外网的原始凭据，首次引导仍承诺“密钥永远不会交给它”。[01，L65–97](source/01-产品定位与设计锚点.md?plain=1#L65-L97) [01，L147](source/01-产品定位与设计锚点.md?plain=1#L147) [04，L429–437](source/04-界面设计.md?plain=1#L429-L437)
- **证据：**主流程序要求无需改造；引用模型又禁止 env/文件，只规定启动时的单向内存注入，没有给出目标进程如何消费该秘密的适配契约。[01，L26–30](source/01-产品定位与设计锚点.md?plain=1#L26-L30) [02，L225–239](source/02-模块设计.md?plain=1#L225-L239) [03，L480–493](source/03-接口契约.md?plain=1#L480-L493)
- **建议决策：**首版只做代理注入，或将引用模型正式定义为显式批准的业务凭据例外，并统一文案、威胁模型与验收。按应用/协议给出读取契约及兼容验证；不能将“送到 guest 内存”直接等同于“现成 CLI 可用”。
- **建议验收：**代理模式验证 guest 不获得原始秘密；引用模式按明确例外验证，界面不得继续展示绝对不交付承诺。

### R03 · “零输入”硬验收与手动粘贴兜底、来源占比 KPI 混为一谈

**影响阶段：M2 的场景验收与产品承诺发布前。**

- **证据：**三类指定场景要求用户输入明文敏感字符数等于零，但 M2 保留手动粘贴；接口把统计目标改为 `origin === 'manual'` 的占比趋近于零，界面数据库示例也允许手动输入。[01，L26–30](source/01-产品定位与设计锚点.md?plain=1#L26-L30) [02，L181–194](source/02-模块设计.md?plain=1#L181-L194) [03，L360–375](source/03-接口契约.md?plain=1#L360-L375) [04，L350–356](source/04-界面设计.md?plain=1#L350-L356)
- **建议决策：**分别定义“沙箱内不输入明文”的安全门槛、“指定场景用户完全不经手明文”的验收、手动录入占比的体验 KPI。明确没有可导入秘密源时的支持范围，不用趋近于零代替严格为零。
- **建议验收：**对 Anthropic、GitHub MCP、内网数据库逐项列出可用认证路径、前置条件和失败结果。Provider 示例中的 OAuth 占位项不能当作已完成接入的证据。[03，L580–615](source/03-接口契约.md?plain=1#L580-L615)

### R04 · P0 已有分期，但与可运行主路径、安全留证的依赖不闭合

**影响阶段：首版范围冻结前。**

- **证据：**P0 仅 M1、M4、文件与网络简化审查；M2/M5/M6 在 P1。模板需要账号，主推最小权限路径又依赖 M5 补授，核心价值验收包括外部 API 与阻断留证。[02，L73–76](source/02-模块设计.md?plain=1#L73-L76) [02，L99–106](source/02-模块设计.md?plain=1#L99-L106) [02，L328–338](source/02-模块设计.md?plain=1#L328-L338) [01，L26–30](source/01-产品定位与设计锚点.md?plain=1#L26-L30)
- **建议决策：**选择 P0 是内部隔离验证版，还是可使用的 Agent 沙箱。前者明确不承诺完整 Agent 闭环；后者至少纳入凭据使用、固定授权及留证的最小后端能力。完整档案 UI 可以后置，不能把安全基础能力一起按模块整体后置。
- **建议验收：**补一张按阶段划分的支持矩阵：工作负载、认证方式、网络/文件权限、补授、审计、生产迁移分别是支持、受限还是不支持。

### R05 · 逐项裁剪与“高风险必须勾满才可运行”冲突

**影响阶段：M3 交互冻结前。**

- **证据：**模块允许取消部分能力后运行；首次审查线框要求未勾满高风险项则禁用确认，原型 `syncReview()` 也强制勾满。[02，L323–335](source/02-模块设计.md?plain=1#L323-L335) [04，L133–136](source/04-界面设计.md?plain=1#L133-L136) [原型，L880–890](source/prototype.html#L880-L890)
- **建议决策：**允许对当前选择的子集形成完整批准/拒绝记录。若确有不可缺少能力，应明确其必要性与功能后果，而不是默认全部高风险能力都必需。
- **建议验收：**允许文件改动但拒绝付费账号调用，仍能按该子集启动；拒绝项不被推荐配置、补授默认值或低风险策略恢复。

### R06 · 写时复制的默认保护与界面选择不一致，回写/丢弃规则需补齐

**影响阶段：宿主代码编辑场景上线前。**

- **证据：**定位与 Workload 示例规定 CoW 默认开启，改动确认后才回宿主；原型默认选中直接“读取并修改”，确认后生效是未选中的独立选项。[01，L36–40](source/01-产品定位与设计锚点.md?plain=1#L36-L40) [03，L45–49](source/03-接口契约.md?plain=1#L45-L49) [原型，L570–581](source/prototype.html#L570-L581)
- **待决边界：**原文已有显式导出与退出销毁，但未给出未导出修改是否提示、宿主原文件已变化时如何处理回写冲突。[01，L218–224](source/01-产品定位与设计锚点.md?plain=1#L218-L224) [02，L437–458](source/02-模块设计.md?plain=1#L437-L458)
- **建议决策：**统一默认保护为明确的一种语义；直接落盘与 CoW 分开表示风险和额外确认。明确冲突检测、回写失败与未导出退出的规则，不无提示覆盖宿主并发修改。
- **建议验收：**默认运行期间宿主文件不变；确认回写前人为修改宿主同一文件，不能静默覆盖；退出时按已确认的导出/丢弃规则处理。

### R07 · `policy.source` 与 Workload 内权限描述的权威关系、指纹绑定未定义

**影响阶段：策略执行与策略导入前。**

- **证据：**策略声明唯一真相，但 WorkloadSpec 与 Policy 分别包含文件/网络/秘密权限；强制启动校验只说明绑定 WorkloadSpec 指纹，没有定义两份描述的合并关系、selector 绑定与 Policy 变化的重审条件。[03，L9–12](source/03-接口契约.md?plain=1#L9-L12) [03，L43–69](source/03-接口契约.md?plain=1#L43-L69) [03，L172–207](source/03-接口契约.md?plain=1#L172-L207) [03，L377–401](source/03-接口契约.md?plain=1#L377-L401)
- **建议决策：**明确三者是否分别是“请求”“策略上限”“用户实际授予”，确定求交/覆盖/拒绝规则，以及哪些内容进入签名、哈希和重新审查条件。
- **建议验收：**只更改 Policy 放宽网络、只变更 Workload 请求或替换 selector 绑定，分别得到确定且一致的拒绝/重审结果。

### R08 · 运行实例、有效期、取消与启动回滚缺少统一终结契约

**影响阶段：M4/M5 实现前。**

- **证据：**授权仅绑定 `workloadId`，`expiresAt` 可选；强制校验未列有效期，裁决未定义运行实例及请求关联标识。多步启动配置挂载、网络、秘密后才启动进程，异常表未规定中途失败/取消的回滚。[03，L377–427](source/03-接口契约.md?plain=1#L377-L427) [02，L392–416](source/02-模块设计.md?plain=1#L392-L416) [02，L447–458](source/02-模块设计.md?plain=1#L447-L458)
- **证据：**一次性模式说退出即销毁，崩溃路径又保留沙箱 30 秒，未说明保留的是资源、权限还是仅诊断数据。[01，L218–224](source/01-产品定位与设计锚点.md?plain=1#L218-L224) [02，L453](source/02-模块设计.md?plain=1#L453)
- **建议决策：**明确单实例限制或引入运行/裁决关联标识；定义超期、撤销、停止、重启、迟到批准和待决请求的生效边界。补齐启动失败、取消、崩溃、应用强退时的清理责任，特别是有秘密/权限的实例不得在未清理的情况下回预热池。
- **建议验收：**启动中每一步注入故障或取消后均无残留授权；停止旧运行后到达的确认不能授权新运行；崩溃保留期间的权限和数据遵循明确规则。

### R09 · 网络授权在界面、schema 与执行通道之间不能得到唯一解释

**影响阶段：网络能力实现与 M3 冻结前。**

- **证据 A：**界面允许批准“互联网上的任何地方”，但通用 schema 禁止 `*`，只提到尚未给出契约的高风险特殊工作负载类型。[04，L160–178](source/04-界面设计.md?plain=1#L160-L178) [03，L100–112](source/03-接口契约.md?plain=1#L100-L112)
- **证据 B：**示例提供 `via: direct`，Broker 通道又要求 guest 无网络栈直连、全部经代理。[03，L55–63](source/03-接口契约.md?plain=1#L55-L63) [03，L480–488](source/03-接口契约.md?plain=1#L480-L488)
- **建议决策：**分别决定普通工作负载是否能申请任意主机，以及 `direct` 是否仅指 Broker 内不注入凭据的转发。不能让用户批准一种系统无法合法存储的权限，也不能让字段名称暗示绕过唯一裁决点。
- **建议验收：**UI 可选择的每个网络范围都能编码为合法策略；任何转发模式仍有明确的 allow-list 执行者和拒绝记录。

### R10 · MCP 未知工具集的继续运行、指纹重审与调用拒绝路径冲突

**影响阶段：MCP 支持上线前。**

- **证据：**模块允许探查失败后继续，每次工具调用交 M5 确认；接口又要求工具指纹变化暂停重审、非 allow-list 工具直接错误，失败探查仍需返回指纹和工具数组。[02，L148](source/02-模块设计.md?plain=1#L148) [02，L357–363](source/02-模块设计.md?plain=1#L357-L363) [03，L501–530](source/03-接口契约.md?plain=1#L501-L530) [03，L553–575](source/03-接口契约.md?plain=1#L553-L575)
- **建议决策：**定义 `unknown` 与“已知空工具集”的区别，以及 unknown → 首次发现 → 待批准 → 已批准/拒绝的转换；确定首次发现是否进入逐次确认或阻断重审。不得将未知工具静默视为已批准。
- **补充：**零权限试探属于文中已明确说明的运行前审查例外，不作为“完全未考虑风险”另报问题；但该例外不能推导为未知工具已获得业务权限。[02，L128–130](source/02-模块设计.md?plain=1#L128-L130)

### R11 · 越界补授与“已挡下 N 次”缺少可对齐的事件契约

**影响阶段：最小权限补授、M6 与运行面板验收前。**

- **证据：**文件越界在挂载层失败、不到 Broker；模块又把文件越界作为 M5 的 Broker 输入，最小权限主路径依赖补授。[03，L480–487](source/03-接口契约.md?plain=1#L480-L487) [02，L500–514](source/02-模块设计.md?plain=1#L500-L514) [02，L549](source/02-模块设计.md?plain=1#L549)
- **证据：**界面要求阻断计数、最近目标和实时活动，接口关系图使用 `RuntimeEvent`/`ArbitrationRecord`，但没有给出相应结构和计数规则；原型固定样例不能补足协议定义。[03，L312–327](source/03-接口契约.md?plain=1#L312-L327) [04，L237–267](source/04-界面设计.md?plain=1#L237-L267) [原型，L933–950](source/prototype.html#L933-L950)
- **建议决策：**规定拒绝事件的可信来源和到 M5 的路径，区分永久禁止与可申请范围；补齐事件/运行/裁决标识、顺序、重连去重、超时与聚合计数口径，并明确补授后重试还是恢复原操作。
- **建议验收：**未挂载目录的拒绝能按规则留证/申请；重复请求、超时、重连不造成丢记或重复计数；禁止路径不会仅因补授 UI 出现而可被授予。

### R12 · 生产允许显式降级，不能同时按“安全边界原样迁移”验收

**影响阶段：M7 / P2 投递能力冻结前，不应反向扩大 P0。**

- **证据：**产品定位承诺安全边界原样带到生产；编译表却允许 CoW 无等价、代理注入降为内存注入、生产无 MCP 工具过滤，只要求显式列出降级。[01，L18–20](source/01-产品定位与设计锚点.md?plain=1#L18-L20) [03，L248–258](source/03-接口契约.md?plain=1#L248-L258)
- **建议决策：**区分“等价投递”与“非等价投递”；定义不可降级保护、阻止投递条件及是否需要重新审批。显式告知是必要条件，但不能代替对失去保护的授权。
- **验证边界：**本评审不认定表内 K8s/FQDN、安全组、sidecar 等目标能力已经可用或等价，后续需按选定环境核对官方能力并实测。
