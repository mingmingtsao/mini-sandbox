# 桌面级安全沙箱：设计评审

## 结论

授权默认拒绝、秘密双轨边界、默认副本写入及冲突回写规则已明确，并纳入设计修订。首版范围、策略来源、运行生命周期等仍需继续确认。设计修订不等于真实沙箱的安全与兼容性已通过验证。

## 已明确的规则

| 评审项 | 修订决定 | 验收 |
|---|---|---|
| R01 授权边界 | 未授权默认拒绝，显式拒绝不能被风险分类覆盖；风险等级只决定提示方式；补授必须完整审查并记录后生效。 | [AUTH-01～03](ACCEPTANCE.md#授权) |
| R02 秘密模型 | 代理模式的原始凭据不进入 guest；引用模式向指定进程交付明文，需明确批准及风险告知。引用接入限定为有明确读取契约且验证通过的适配器，未适配程序阻断，不自动转为环境变量或磁盘文件。 | [SECRET-01～05](ACCEPTANCE.md#秘密) |
| R05 部分批准 | 用户可只批准所选能力启动；未勾选项保持拒绝，不能因其它项被批准而自动恢复。 | [AUTH-02](ACCEPTANCE.md#授权) |
| R06 文件保护 | 默认只修改沙箱副本，宿主确认后回写。宿主变化时阻断并展示三方差异；取消、解决冲突后重审或明确覆盖所选文件。写入前再次校验，宿主再次变化使旧确认失效。 | [WRITE-01～07](ACCEPTANCE.md#文件回写) |

规范见 [产品定位与设计锚点](source/01-产品定位与设计锚点.md)、[模块设计](source/02-模块设计.md)、[接口契约](source/03-接口契约.md)、[界面设计](source/04-界面设计.md)。原型用于演示这些决策；真实凭据交付、文件并发控制和隔离能力仍需实现验证。

## 待决事项

### R03 · “零输入”的验收口径

当前设计已区分交付边界与录入方式，`SecretRef.origin` 也已明确仅用于手动来源占比。待确认的是各服务的 OAuth、导入与宿主粘贴支持情况及体验目标，不将减少手工输入写成全部场景均已实现零输入。

来源：[01 §1.2](source/01-产品定位与设计锚点.md)、[02 §3.2](source/02-模块设计.md)、[03 §B.2.2](source/03-接口契约.md)。

### R04 · P0 与主路径依赖

P0 包含 M1、M4 与简化 M3；账号保管、实时补授、信任档案在 P1。模板需要账号，最小权限主路径依赖补授，核心价值还要求留证。需确定 P0 是内部隔离验证版，还是能完成外部 API 调用的 Agent 沙箱，并按阶段列出支持矩阵。

来源：[02 §1、§2.2、§4.3](source/02-模块设计.md)、[01 §1.2](source/01-产品定位与设计锚点.md)。

### R07 · 策略唯一来源与合并规则

`policy.source` 声称唯一真相，WorkloadSpec 与 Policy 却分别描述权限。需明确请求、策略上限、用户实际授予之间的关系，以及 selector 绑定、求交/覆盖规则、签名内容和重新审查条件。

来源：[03 §0、§A.1、§A.2、§B.2.3](source/03-接口契约.md)。

### R08 · 通用运行生命周期

秘密交付和回写已补充运行绑定、撤销或过期检查，但通用运行状态机仍需统一：并发实例策略、停止后的待决请求终结、启动中失败回滚、崩溃保留 30 秒期间的权限和清理责任。应区分历史审查复用与本次执行授权，避免旧确认授权新运行。

来源：[02 §5.3、§5.6](source/02-模块设计.md)、[03 §B.2.3、§B.2.4](source/03-接口契约.md)。

### R09 · 网络授权的可表达性

界面允许选择“访问互联网上任何地方”，通用 schema 禁止通配主机；特殊高风险类型尚无完整契约。`via: direct` 也需明确是否仅指经 Broker 的不注入凭据转发，不能让用户批准一种系统不能保存或执行的范围。

来源：[03 §A.1.2、§B.3](source/03-接口契约.md)、[04 §2.3](source/04-界面设计.md)。

### R10 · MCP 未知工具集

探查失败后逐次确认、工具指纹变化暂停重审、非 allow-list 工具直接拒绝之间，仍需明确唯一状态转换。`unknown` 不能等同于已知空工具集，更不能视为已授权；首次发现工具应有确定的审查入口。

来源：[02 §2.5、§4.5](source/02-模块设计.md)、[03 §C.1](source/03-接口契约.md)。

### R11 · 越界事件与补授

文件越界在挂载层失败、不到 Broker，但补授和运行面板依赖可信拒绝事件。需明确事件产生者、上报路径、可申请与永久禁止范围、补授后的重试语义，以及事件标识、运行绑定、重连去重、聚合计数规则。

来源：[02 §6.3、§6.6](source/02-模块设计.md)、[03 §B.1、§B.3](source/03-接口契约.md)、[04 §3](source/04-界面设计.md)。

### R12 · 生产投递的非等价保护

产品定位改为策略导出用于生产部署。投递契约已要求无法维持 CoW 回写或代理保护时阻止相应投递，但 MCP 工具过滤等其它能力仍有不等价情况。需继续明确等价/非等价投递的划分、其它不可降级保护与重新审批条件。代理到引用的转换必须遵守新的秘密交付边界，不能仅告知后自动降级。

来源：[01 §1.1](source/01-产品定位与设计锚点.md)、[03 §A.2.2](source/03-接口契约.md)。
