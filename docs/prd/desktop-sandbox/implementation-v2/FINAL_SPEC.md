# mini-sandbox 最终实施方案 v2

日期：2026-10-23｜状态：产品候选实施基线，待 Review；不是已实现或已通过安全测试的声明。

输入：赛题原文、比赛规则、已合并 PR #1 的产品设计与早期设计快照 `54c0e6f3d9541b47f9ee1fd3b363ef63b813fd28`、前期技术方案。

**决策：保留 #1 的用户心智、后果解释和审查快照；采用上一版的收敛执行面；补齐运行身份、实际操作授权和证据来源。不是取两版功能的并集。**

## 1. 产品边界与交付定义

### 1.1 一句话

在 Mac 上运行已有 AI Agent，用户选择项目副本和允许使用的服务即可工作；长期凭据不交给 Agent，敏感外部操作由宿主授权，结果由用户审阅导出。

赛题只要求“不在沙箱内填写敏感信息”，没有要求“用户从不在任何地方粘贴 API key”。本产品选择更强的默认保护：原始长期凭据不进入不可信执行域；录入、OAuth 和连接管理发生在宿主。支持宿主安全录入符合原题，不是安全降级。

### 1.2 必须达到的完整闭环

连接服务 → 选择 Agent 与项目 → 确认本次权限 → 真正运行/改文件/跑测试/调 MCP → 必要时审批 → 查看结果 → 导出 → 停止并撤权。

Claude Code、Codex、DSH 全部保留为目标，采用固定实测版本和认证模式；先实现一个只是顺序，不是删去另外两个。API 认证、订阅登录、TUI/headless、MCP、恢复会话分别记录，不能混称“兼容”。

### 1.3 首版平台与非目标

以 Apple Silicon macOS 为首个构建/验收平台；最低系统版本和资源要求由真实开发 Mac 与框架探针确定，不虚构版本、启动速度或常驻内存数据。

本次不实施：云/K8s投递、云计费、Windows/Linux桌面端、Intel承诺、多 Agent 并发管理、预热池、持久 VM、任意互联网、任意脚本安装、自动覆盖原项目、自动导入各种秘密管理器、任意未知协议的透明安全兼容。

这些非目标不得被用来掩盖赛题硬要求的缺口。尤其“所有主流 MCP”仍需形成明确清单并实测：未确定清单不等于已经全覆盖。支持目录缺项必须列在交付限制中。

### 1.4 安全保证及前提

保证目标：不读取未导入宿主文件；不向 Agent/不可信本地 MCP 投递原始长期凭据；外部请求只能经过受控执行点；未批准操作不被转发；停止后不再获得新授权；导出不越界。

前提：宿主 OS、虚拟化框架、宿主应用/策略代码及被绑定的上游凭据接收服务按其角色可信。远端响应、工具描述、模型输出仍按不可信数据处理。

不保证：抵抗已攻陷宿主、全部未知虚拟化漏洞、硬件侧信道、授权数据通过已批准模型渠道外发、远端服务自身恶意使用其已有权限、用户之后主动执行导出的恶意代码。停止不撤回已经发给远端的数据，不回滚已经发生的外部副作用。

## 2. 用户体验：少量页面，真实状态

保留三类导航：**工作台、服务连接、活动与结果**。程序/模板管理嵌入工作台；高级参数放详情，不建立一整套企业管理后台。

| 环节 | 用户操作 | 产品必须呈现 |
|---|---|---|
| 首次启动 | 检查并准备环境 | 真实镜像/资源准备进度，明确失败原因，不能退回宿主裸跑 |
| 服务连接 | 登录或在宿主录入测试凭据 | 服务身份、账号别名、可用权限、凭据所在边界、测试/撤销 |
| 创建任务 | 选Agent、文件夹、连接 | 导入范围、排除项、大小预检；不用写JSON或环境变量 |
| 运行前检查 | 确认选择的授权子集 | “改的是副本”“哪些内容可能发给模型”“哪些外部动作会询问” |
| 工作台 | 输入任务/使用Agent终端 | 状态、权限摘要、实际请求活动、明显且可立即使用的停止按钮 |
| 敏感操作 | 宿主原生确认 | 服务、动作、具体资源和关键参数；拒绝为默认，关闭/超时即拒绝 |
| 结果 | 看差异，选新目录导出 | 不覆盖原项目；未导出提醒；导出后也不自动执行内容 |

默认模板是“最小够用”：工作区副本 + 用户选择的模型 + 所需只读服务；写外部系统逐次确认。不是“去掉所有中高风险能力，让正常任务反复失败后再补授”。

不要求把全部高风险项勾满才能启动。真正不可缺少的能力缺失时，提示准确功能后果；可进入离线模式，但不能显示“模型已就绪”。

审批权限由宿主独立控制；终端/网页内容没有创建批准的接口。避免绝对文案“伤不到你的Mac”“用完不留任何痕迹”“隐藏工具后AI永远不知道”。不声明原生视觉不可被世界上任何软件模拟；关键保证是 guest 不能把渲染内容变成有效授权。

停止与关窗区分：关闭单个任务界面询问停止/保留查看；首版应用退出会停止会话与撤权。未导出结果的保留/删除规则可见，不为安全感伪造立即物理擦除承诺。

## 3. 技术架构与主体身份

### 3.1 选定架构

```text
macOS 原生应用（可信域）
  SwiftUI / 原生审批 / 连接管理 / 结果审阅
  Host Core：VM管理、策略、Keychain访问、审计、导入导出
          │
          ├── 固定模型服务适配器 ──TLS── 绑定的受信模型服务
          ├── MCP网关/服务适配器 ─TLS─ 绑定的远端MCP/API
          │
          ├── 按VM对象绑定的有界vsock数据通道
          │       └── Agent VM：guest bridge + CLI + 项目副本
          │           无通用网卡、无宿主共享目录、无真实长期凭据
          │
          └── 可选独立连接器VM：固定版本stdio MCP
                  无通用网卡、无原始长期凭据
                  只用宿主授予的指定服务路由
```

采用 Apple Virtualization.framework 与 Virtio socket。[W1] 首版不做通用 TLS MITM、任意 HTTP CONNECT、任意宿主 URL 转发或 guest shell→host shell 桥接。没有 NIC 是减少出口，不是完整安全证明；vsock解析器、终端渲染、文件接收和宿主适配器仍是攻击面。

技术栈确定为 Swift/SwiftUI 宿主，Go guest bridge，固定 Linux arm64 镜像。核心逻辑可脱离 GUI 测试；终端组件固定上游版本，不另写完整终端模拟器。首版 Host Core 可在同一应用进程内模块化，不为了画边界拆多个守护进程；同进程时不能宣称 UI 与 Keychain 在 OS 权限上隔离。未来拆进程需另验 IPC 对端身份和权限。

### 3.2 身份不能由消息自报

Host Core 创建 Run 对象与 VM，并把监听器/连接绑定到该对象。数据包里的 runId、workloadId 只可用于核对，不授予身份。每个 VM 到每个服务的路由都必须从宿主授权表查出。

guest bridge、guest root、MCP进程都不能扩大宿主路由。即使整个 Agent guest 被控制，也只能使用该运行已经授予的能力；不能因猜到另一 runId 获得别人的连接。

不同敏感信任域不共用一个 guest 内核。可有两种明确布局：

- 本地无秘密文件助手与 Agent 共用同一项目副本：同一个信任域，不对彼此隔离作承诺。
- 需独立连接权限的 MCP：独立连接器 VM，通过宿主中介通信；不能访问 Agent workspace，除非明确复制了所需数据。

初版只允许运行一个 Agent 会话和必要的一个连接器实例；后续并行扩展不改变身份机制。

### 3.3 数据面与控制面

vsock只提供：会话绑定的模型请求、允许的MCP消息、受限文件传输、PTY输入输出和诊断。消息有长度、并发、超时、深度等上限；未知类型默认拒绝。

**不能从 guest 调用：**创建连接、改变策略、批准动作、读取Keychain、任意文件系统访问、创建新VM、切换宿主账户绑定。宿主UI的批准必须关联 Host Core 中尚未消费的对象，不接受“approved:true”之类 guest 断言。

## 4. 凭据、模型与 MCP：按机制兼容，不按名称许诺

### 4.1 统一连接模型

Connection 由宿主保存：固定服务/issuer/endpoint、账号别名、Keychain引用、授权范围、适配器版本、允许的上游、验证状态。guest仅得到本地路由和必要的占位值或短期本地能力凭证；后者仍是敏感权限材料，限权限时可撤销，不能公开日志化。

真实凭据仅由宿主在使用时读取，并按已绑定服务发送；不响应 guest 自选的 credentialRef、认证头格式、任意 URL 或重定向目标。服务端可能接收原始认证材料，因此“保存在宿主”不等于“秘密从不发送给任何服务”。

OAuth按所支持协议的正式流程实现，固定 issuer/resource/audience，校验 state、PKCE（适用的授权码流程）、精确回调、过期与撤销；不把A服务token透传给B服务。[W2][W3] 产品未注册/未验证的OAuth入口不能显示“一键登录已支持”。

宿主手动录入是可用的正常路径。Keychain存储、日志不回显、占位配置与最小权限更重要；不承诺内存中最多一份或所有库副本即时零化。

### 4.2 模型适配器

Claude Code、Codex、DSH按固定版本验证入口、配置键、模型协议、流式响应、取消、错误、MCP调用与测试执行。使用官方支持的 gateway/base URL 入口；这些入口的存在不代表所有认证模式兼容。[W6][W7]

模型路由不只是域名：宿主固定必要的API路径/方法/请求字段，去除 guest 自带上游认证头；限制模型、最大输出、并发/次数等可执行额度。价格估算不能冒充绝对账单硬上限。网络非关键探测/遥测被拒绝时，不能自动认定Agent恶意或把拒绝计数当成果。

模型请求可能包含项目内容，UI在授权时明示；不承诺通用数据防泄漏。禁止因遇到认证问题把真实key写进guest“临时解决”。

### 4.3 MCP接入矩阵

| 类型 | 实现路径 | 安全声明与未满足时的行为 |
|---|---|---|
| 远端HTTP、API key | 宿主网关连接固定受信endpoint并注入认证 | Agent不获得key；需服务/资源适配才能进一步保证只读/资源范围 |
| 远端HTTP、OAuth | 宿主浏览器登录、刷新、撤销 | token只给绑定服务；声明具体scope与实测版本 |
| 本地stdio、无秘密、只操作副本 | 同域助手或独立VM，位置明确 | 同域时不得宣称Agent与助手互相独立隔离 |
| 本地stdio、令牌只用于HTTP认证 | 固定连接器VM + 占位令牌 + 可配置的宿主服务endpoint；逐个适配 | key不进入连接器；必须实际验证该程序支持endpoint/认证替代，不假设通用可用 |
| 密码协议、HMAC/私钥签名、未知CLI | 需要专用受信协议/签名适配器；没有则不启动该认证模式 | 不提供自动原始秘密memory-inject；这是兼容缺口，不装作完成 |

“凭据型stdio”必须验证一个真实目录项的完整路径；只有无凭据filesystem示例不能代表其完成。无法适配的项目列为缺项。远程优先是路径选择，不是把本地MCP要求消掉。

比赛首轮覆盖类别：GitHub类代码服务（资源限定、只读与审批写）、一个确实可接入的OAuth远端服务、本地工作区stdio、一个可代理认证的stdio。具体产品与版本先在候选目录中核实账号和官方实现，再固化；这些类别不是“全体主流”的替代定义。

### 4.4 协议网关必须有完整拒绝面

选择并固定支持的 MCP 协议版本/能力集，协商结果进入证据，不盲目按旧版假设透传新版消息。除 tools/list 和 tools/call，还要明确处理 resources、prompts、roots、sampling、elicitation及所选版本支持的服务器发起消息；未支持者不发布能力并拒绝，不让它们成为绕过策略的旁路。[W2][W3]

工具目录分 unknown/known-empty/known-ready；unknown不是“允许全部后逐次问”。无凭据探查在有CPU/内存/时限但无宿主数据与外部授权的环境中执行，称“受限探查”，不声称没有任何权限或副作用。需要认证才能枚举的服务，先在宿主明确连接该服务，再在限制下发现能力。

目录缓存绑定服务身份、版本、工具名和schema指纹。更新导致相关接口变化时暂停受影响连接重新核实；不得仅因名称相同就继承旧语义。工具名/描述来自不可信服务时仅作为展示数据，不直接生成高权限规则。

### 4.5 请求权限与实际业务权限分开

对通用远端MCP，只能保证网关未发出未经批准的消息，不能保证该远端内部没有其他行为。更强的“只读/仅指定仓库”要求可信服务适配器与上游权限配合：测试账号尽量只对目标仓库有相应权限；校验参数中实际owner/repo/page/path而不只校验工具名；写操作经具体审批。

本地连接器即使拿不到key，也能滥用被允许的认证路由。因此该路由不能是“给 api.github.com 的任何请求都加管理员token”。每个路由固定方法/资源/动作；需要任意 GraphQL 或私有协议却无法可信解析时，不声明细粒度只读，改用已验证的受限路径或标为不支持。

入口工具的一次批准不能变成连接器的全局写权限。实际认证出站点也要核对已批准动作对应的方法、资源和有效载荷；不能用“未来几秒允许写”的时间窗口替代绑定。若现成连接器无法提供足够关联信息，则由宿主受信适配器执行该写动作，或只开放可在上游强制的只读模式，不能宣称逐次审批已经覆盖真实副作用。

## 5. 唯一授权模型与关键契约

### 5.1 权限关系

```text
实际可执行范围
  = 产品硬限制
    ∩ 受信适配器已实现且验证的范围
    ∩ 本次用户授予
    ∩ 上游身份自身可用权限
    − 显式拒绝项
```

WorkloadSpec表达“想运行什么/请求什么”；模板/产品策略表达上限；用户选择形成Grant；RunGrant是当前运行的不可变授权快照。用户导入的YAML不能自己证明批准。风险等级只控制显示/是否额外审批，不扩权。

首版不提供看似可撤销但无法抵抗guest root的“禁止fork”承诺。运行时模板的进程和资源约束是工程限制，外部资源授权在宿主执行；本地文件已复制给guest后无法撤回其已读知识，需要停机重建才能收窄其未来可见副本。

### 5.2 最小逻辑契约（语言无关；非已实现API）

```text
RunGrant {
  run_id, epoch, created_at, expires_at,
  workload_image_digest, agent_adapter_version,
  workspace_snapshot_id,
  policy_digest, user_approval_snapshot_id,
  connections: [{connection_id, account_binding_version, scopes, route_version}],
  explicit_denies, resource_limits
}

PendingAction {
  action_id, run_id, epoch, grant_digest,
  connection_id, tool_or_operation, schema_digest,
  canonical_parameters_digest, resolved_resource,
  safe_display_snapshot, nonce, expires_at,
  state: pending | denied | expired | consumed
}

SecurityEvent {
  event_id, host_sequence, run_id, action_id?, time,
  origin: host_enforcement | guest_diagnostic,
  operation, resource_summary, decision, reason, grant_digest,
  outcome: not_dispatched | completed | failed | unknown
}
```

对重复JSON键、不明确的资源解析或无法稳定规范化的请求直接拒绝。宿主保存 canonical request 的实际内容，不把digest当成内容。批准后原子消费的是同一个待决对象；不得在批准后重新从guest取“最终参数”。签名/HMAC有助于跨进程传输完整性，但不能替代可信控制面；同进程内host-only对象也不能被guest自报JSON替代。

Grant有运行实例与必填有效期。旧run、旧epoch、已撤销连接、工具schema变化、过期、被拒或已消费nonce，均不能授权新操作。

### 5.3 一次副作用请求的执行次序

验证消息与身份 → 校验范围 → 生成不可变动作 → 原生审批（需要时）→ 原子重查run/epoch/连接有效性并消费动作 → 持久记录dispatch意图 → 调用上游 → 记录结果。

撤销与dispatch的线性化点在Host Core内确定：撤销生效后不再启动新的dispatch；已越过dispatch点的请求尽力取消但可能已执行。外部副作用超时或崩溃恢复后不确定时记 unknown，禁止自动重试。上游有可靠幂等键时可利用，但不宣称所有服务都有。

关闭窗口、Esc、审批超时和停止任务都产生明确拒绝/撤销，不能仅隐藏UI。待决动作数量和到期时间有上限，重复请求可聚合显示但不把多个不同动作合并成一个无限许可。

## 6. 文件、镜像与依赖

源文件夹通过宿主系统Picker选择。导入生成预览和清单，默认排除已知秘密文件、宿主凭据配置、不必要的.git配置与hooks；这只能降低风险，不能发现任意内容中的全部秘密。

导入不跟随逃出选择范围的链接。拒绝绝对路径、..穿越、设备/管道/特殊文件；限制数量、体积和路径长度。导出到用户新选目录，安全创建目标，不执行guest产物，不把不可信tar直接解包到宿主。处理大小写/Unicode归一化后重名、符号/硬链接、并发替换和不完整传输；以临时落点验证后完成，取消时不写坏目标。

初版不覆盖原目录。界面展示完整增删改清单和基础diff；二进制/超大内容不能预览时明确标注，不假装审阅过全部字节。

镜像由独立构建步骤准备，包含固定Agent/语言运行时/演示项目工具链；来源、版本、digest、构建脚本、许可记录进入制品清单。镜像构建可以联网，运行会话不继承构建权限或凭据。每次运行创建独立可写状态，不能把“上一轮已撤权的污染磁盘”当干净实例。

任意apt/npm/pip在线安装不属于首版承诺。运行前明确检测项目所需工具链；若缺失，提示未支持或由单独审查的依赖准备流程产生新固定镜像。不要半途为安装依赖开放所有外网。用真实仓库的构建/测试证明当前支持范围，而不是只演示Agent回一句话。

## 7. 生命周期与故障

```text
CREATED → PREPARING → READY → RUNNING → STOPPING → STOPPED
                    ↘ FAILED        ↘ FAILED
```

模型/MCP调用的PendingAction状态独立于Run。任务停止时先阻止新操作、增加epoch/撤销授权、拒绝待决审批，再取消连接与停止VM。UI显示“停止中”直至确认，不仅改一行状态文字。

启动每一步都有清理责任：磁盘、临时文件、服务路由、待决动作和连接器绑定。任何阶段失败/取消都不能留下可用授权。App崩溃/设备重启后按实际VM与状态核对，历史Grant不自动恢复有效；新运行要新runId与新授权。

Broker/策略异常拒绝新请求；不得直连、复制真实key或宿主裸跑。审计无法持久写入时不允许新的受权外部dispatch，也不接受新运行，已在途请求记不确定结果并停止进一步扩展。

首版不做预热池和持久VM。启动慢只能显示真实进度、取消或优化实现，不能静默改为更弱的生命周期。临时工作数据由结果管理按明确保留/丢弃规则清理；VM停机不等于所有SSD字节完成安全擦除。

## 8. 审计与信任表达

可信事件由Host Core执行点产生，标识主体、运行、操作、资源、授权版本、决定和结果；guest输出属于非可信诊断，不能提高安全计数或批准请求。必须能从GUI计数追溯到去重后的event_id。

UI显示“网关已拒绝N次请求”，其中N只统计有宿主拒绝证据的操作。正常程序缺权限/网络探测与攻击不是同一概念，不把所有拒绝包装成拦截攻击。不提供没有探测覆盖的“目前没有任何攻击”结论。

日志不记录真实认证材料，不默认保存完整提示词、请求体和敏感文件内容。导出诊断预览/脱敏。append-only是写入策略，不宣称可抵抗已控制宿主用户或root的篡改。保留审批时的具体文案与参数显示快照，文案升级不回写旧记录。

## 10. 测试、验收与可证明程度

ACCEPTANCE.md 提供 37 项产品功能、安全与发布验收用例，全部 NOT_RUN；这是待实现验收规格，不是已执行的测试或可运行的测试套件。

测试分层：无凭据单元测试、模型/MCP协议fixture、真实Mac VM测试、最小权限真实账号联调、打包GUI测试、非实现者体验。fixture成功不能替代外部服务成功，缺环境记BLOCKED，未执行记NOT_RUN。

攻击测试由受控测试程序直接执行，不靠要求模型作恶来证明安全。使用测试凭据、测试仓库和本地可控上游，不以真实个人资产作破坏性样本。扫描未发现秘密是证据之一，必须结合路由、身份和凭据流审查，不是数学上证明永不泄漏。

每条结果保存：case_id、commit_sha、app/image digest、OS/架构、Agent/MCP/协议版本、测试步骤或命令、expected/actual、exit code、证据文件、时间和测试范围。PASS只能来自实际运行，安全硬门禁不能用总体通过率抵消。
