## 0. 界面设计的三条总则

| # | 总则 | 来源 | 可验收的检查点 |
|---|---|---|---|
| G1 | **安全状态必须常驻可见，不藏在二级页面** | 锚点 1 | 任意时刻截图主界面，都能看出"它现在能碰什么、挡下过什么" |
| G2 | **界面不出现技术术语**（措辞表之外的词一律不得上屏） | 锚点 2 / D3 | 全界面文案过一遍措辞表，无法映射的词即为缺陷 |
| G3 | **信任决策界面必须有宿主归属标识**，且不由 guest 渲染 | 02 §6.6 | 所有授权/确认界面带应用图标与"来自沙箱应用"标识 |

**G3 的视觉实现**：所有信任决策界面（审查、补授、敏感确认）使用统一的「安全边框」视觉语言——一个不可被 guest 内容覆盖的原生窗口样式。用户学会识别这个样式，就能分辨"这是沙箱在问我"还是"沙箱里的程序在骗我"。

### 1.1 导航结构选择

**选择：左侧固定侧边栏（macOS 原生 NSSplitViewController）**

`⚖️ 取舍`：
- **侧边栏** vs **标签栏**：侧边栏能常驻显示"正在运行 2 个沙箱"的状态徽标（服务 G1），标签栏不能。
- **侧边栏** vs **菜单栏小工具（menu bar extra）**：菜单栏更轻量、更符合"后台守护"的心智，但审查界面需要足够空间展示能力清单与后果描述——塞进菜单栏弹出层会逼迫文案压缩，违反 G2。
- **最终形态**：主窗口用侧边栏；**同时**提供菜单栏小工具作为状态指示器与快速停止入口（不承载任何信任决策）。

### 1.2 命名的产品考量

| 技术概念 | 界面命名 | 为什么不用原词 |
|---|---|---|
| Secret / Vault | **账号与密钥** | "秘密"在中文里有隐秘感；用户心智是"连接我的账号" |
| Capability Review | **运行前检查** | "能力审查"像合规流程，"检查"更日常 |
| Workload | **程序**（列表中）/ 具体名（卡片中） | "工作负载"是运维术语 |
| Audit Log | **安全档案** | "日志"暗示技术排查，"档案"暗示可回溯的记录 |
| Arbitration | **它想做一件没说过的事** | 不给这个概念命名，直接描述场景 |
| Ephemeral | **用完即焚** | 直观且有记忆点 |
| microVM / 沙箱 | **沙箱** | 保留，这是产品名的一部分，且已有公众认知 |

### 2.2 本界面的六个关键设计

| # | 设计 | 服务于 | 若去掉会怎样 |
|---|---|---|---|
| 1 | **高风险项置顶、默认未勾、需逐项勾选** | D3 否决条件 | 用户会无脑批准，审查形同虚设 |
| 2 | **每项有"后果描述"而非仅能力描述** | 锚点 1 | 用户看得懂字但做不了判断 |
| 3 | **"为什么需要这个"可展开查看依据** | 02 §2.3 | 用户无法质疑系统的推断 |
| 4 | **"你的密钥不会交给它"显式标注** | D1 | 产品最强的安全承诺不可见 |
| 5 | **否定式总结**（它**不能**做什么） | 锚点 1 | 用户只知道给了什么，不知道边界在哪 |
| 6 | **"先用最少权限试试"与主按钮并列** | 02 §4.3 | 失去对审查疲劳的结构性缓解 |

**第 5 点值得展开**：安全感来自边界感。只列"能做什么"，用户的想象是开放的；补一句"不能做什么"，边界才闭合。这一行是整个界面里信息密度最低但心理价值最高的部分。

### 3.2 「已为你挡下 N 次越界尝试」的设计规格

这是整个产品**最有说服力的 UI 元素**——它把"我们保护了你"从承诺变成证据。

| 规格 | 要求 | 理由 |
|---|---|---|
| **零值也显示** | 显示"目前没有任何越界尝试 ✓"，不隐藏 | 否则用户不知道这个指标存在，也就无从建立信任 |
| 展示最近一条 | 带具体目标与时间 | 抽象计数无感，具体事实有感 |
| 一键补授 | 点进去可直接"允许这一项" | 02 §6.2：把"失败→补授→重试"压到 3 秒内 |
| 不用红色 | 用盾牌图标 + 中性色 | 这是**好消息**不是错误；红色会让用户以为出了问题 |
| 可分享 | 右键可复制为文本 | 开发者会想把它发到群里——这是最好的口碑传播素材 |

**"不用红色"这条容易被设计师反对**，但它关乎叙事：阻断成功是产品在正常工作。若用红色，用户的心理是"我的沙箱出问题了"；用盾牌，心理是"沙箱帮我挡住了"。同一事实，两种叙事。

3. **超时自动拒绝且明示倒计时**——用户离开电脑时的默认行为是安全的，且用户知道这一点。

│                                                                      │

│  ├─ 14:32  🛡 挡下  Claude Code 想读取 ~/.ssh/id_rsa                │

**三个设计点**：
1. **"值得注意"置于时间线之上**——主动分析比被动日志有用得多，且"3 项权限从未用过 → 一键收回"是把审计数据反向用于改善安全姿态。
2. **批准记录可展开查看"当时的说明"**——落实 03 §B.2.5 的措辞快照，让事后追溯有据。
3. **底部的隐私声明**——"只存在你的电脑上，不会上传"必须常驻，这是本地优先产品的信任基础。

## 6. 首次启动引导（Onboarding）

四步，全程不要求任何技术决策：

```
第 1 步 ─────────────────────────────────────────────────
  "AI 编程助手很好用，但它拿着你电脑的全部钥匙。"
  [ 插图：一个程序 → 指向 文件/网络/密钥 三个图标 ]
  → 建立问题意识（不先讲产品，先讲问题）

第 2 步 ─────────────────────────────────────────────────
  "我们给它一台独立的小电脑。出了事，伤不到你的 Mac。"
  [ 插图：宿主 Mac 与沙箱分离，中间一道边界 ]
  → D2 的硬隔离叙事

第 3 步 ─────────────────────────────────────────────────
  "它启动时什么都碰不到。你给什么，它才有什么。"
  [ 插图：零权限启动 → 用户逐项授予 ]
  → D2 的零权限叙事

第 4 步 ─────────────────────────────────────────────────
  "你的密钥永远不会交给它。"
  [ 插图：密钥留在宿主侧，沙箱代为转交请求 ]
  → D1，产品最强的承诺放在最后一步（记忆点）

         [ 跳过 ]          [ 开始：跑第一个程序 ]
```

**第 4 步放最后是刻意的**：峰终定律下，最后一屏的记忆最强。"密钥永远不会交给它"是我们相对 Cosmonic 最可验收的差异点（01 §3.1），值得占据这个位置。

**引导结束后直接进入"跑第一个程序"**，默认推荐 claude code 模板——让用户在 2 分钟内完成一次完整的「登记 → 审查 → 运行 → 看见阻断」闭环。**首次体验必须包含一次阻断**：建议在示例工作负载中内置一个会触发越界的无害动作，让用户第一次就看到盾牌亮起。

`⚖️ 取舍`：故意制造阻断有"表演"嫌疑。缓解：该动作必须是真实的（例如示例程序确实尝试读取一个未授权路径），且在档案中如实记录。不是造假，是**选择一个会自然触发保护的示例**。

## 7. 完整措辞表（G2 的执行工具）

> 这是一份**受控词表**。界面上出现的任何能力描述必须来自本表。无法映射的能力不得上线（03 §I6）。
> 版本：`phrasing-table/v1`，写入每条 `ApprovalSnapshot`。

### 7.1 文件系统

| 技术事实 | 🚫 禁用措辞 | ✅ 界面措辞 | 后果描述 | 风险 |
|---|---|---|---|---|
| `mount ro` | 只读挂载 | 能读取「X」文件夹，但不能修改 | 它能看到里面所有文件的内容 | 🟡 |
| `mount rw` | 读写挂载 | 能读取并修改「X」文件夹里的所有内容 | 如果它出错或被动过手脚，这些文件可能被改坏或删掉 | 🔴 |
| `mount rw + CoW` | 写时复制 | 能修改「X」，但改动要你确认后才真正生效 | 它的改动会先放在沙箱里，你看过再决定 | 🟡 |
| `exclude` 命中 | 排除规则 | 「X」里的敏感文件（如密码文件）它看不到 | — | 🟢 |
| 无文件能力 | 空挂载表 | 完全碰不到你的任何文件 | — | 🟢 |

### 7.2 网络

| 技术事实 | 🚫 禁用措辞 | ✅ 界面措辞 | 后果描述 | 风险 |
|---|---|---|---|---|
| `egress: deny` | 出站策略拒绝 | 完全不能联网 | — | 🟢 |
| allow 已知 Provider | 主机白名单 | 能访问「Claude 官方服务」 | 它能和 Claude 通信，会产生费用 | 🟡 |
| allow 自定义主机 | FQDN allow-list | 能访问 example.com | 它能和这个网站交换数据 | 🟡 |
| allow `*` | 通配出站 | ⚠️ 能访问互联网上的任何地方 | 如果它被人动过手脚，你的数据可能被发到任何地方 | 🔴 |
| 代理注入 | header injection | 由沙箱代为转交你的凭证 | 程序本身拿不到密钥 | 🟢 |

### 7.3 秘密

| 技术事实 | 🚫 禁用措辞 | ✅ 界面措辞 | 后果描述 | 风险 |
|---|---|---|---|---|
| `proxy-inject` | 代理注入模式 | 能以你的身份调用「X」 | 会用你的账号产生费用；**你的密钥不会交给它** | 🔴 |
| `memory-inject` | 内存注入 | 能以你的身份连接「X」 | ⚡ 这类服务无法代为转交，密钥会进入程序内存 | 🔴 |
| 秘密已失效 | 凭据 expired | 你的「X」账号好像失效了 | — | 🟡 |

### 7.4 进程与系统

| 技术事实 | 🚫 禁用措辞 | ✅ 界面措辞 | 后果描述 | 风险 |
|---|---|---|---|---|
| `spawn: allow` | fork/exec 允许 | 能在沙箱内启动其他程序 | 这是大多数开发工具的正常需求，不会影响沙箱外 | 🟢 |
| `clipboard: read` | 剪贴板读取 | 能读取你的剪贴板 | 你复制过的任何东西它都能看到，包括密码 | 🔴 |
| `lifecycle: ephemeral` | 临时实例 | 用完即焚 | 关闭后沙箱销毁，不留痕迹 | 🟢 |
| `lifecycle: persistent` | 持久化 | 长期保留 | ⚠️ 沙箱里的改动会一直留着，包括你没注意到的 | 🟡 |

### 7.5 MCP 工具

| 技术事实 | ✅ 界面措辞 | 后果描述 | 风险 |
|---|---|---|---|
| `tools/list` 过滤 | 关掉的功能，AI 不会知道它们存在 | 它不会反复尝试用不了的功能 | 🟢 |
| 读类工具 | 查看 / 列出 / 搜索「X」 | 它能看到你的 X，包括私有的 | 🟢🟡 |
| 写类工具 | 能以你的身份「创建/修改」X | 它的动作会以你的名义发生 | 🔴 |
| 删类工具 | 能以你的身份删除 X | 一旦删除无法恢复 | 🔴 |
| Agent/MCP 隔离 | 这个程序和「X」互相看不见对方的文件和网络 | — | 🟢 |

### 7.6 措辞表的维护规则

| 规则 | 说明 |
|---|---|
| 新增能力必须先进表 | 无措辞 → 不得上线（03 §I6 的流程落点） |
| 改措辞必须升版本号 | 旧 `ApprovalSnapshot` 保留旧措辞（03 §B.2.5） |
| 后果描述写"会怎样"不写"是什么" | 这是用户做判断的唯一依据 |
| 禁用词表需硬编码检查 | CI 中扫描界面字符串，命中 🚫 列即失败 |

**最后一条把 G2 从设计规范变成了工程约束**——建议在构建流程中加入界面文案扫描，命中禁用词表直接构建失败。否则"不出现技术术语"这条会在迭代中慢慢瓦解。

## 8. 状态与异常界面

### 8.1 空状态

| 场景 | 界面 |
|---|---|
| 无工作负载 | "还没有程序。要不要先试试 Claude Code？" + 模板卡片 |
| 无已连接账号 | "还没连接任何账号。连接后，程序就能用你的身份干活，但拿不到你的密钥。" |
| 无安全事件 | "一切正常，目前没有任何越界尝试 ✓"（**不留白**） |

**"无安全事件"不留白是刻意的**（呼应 §3.2）：空白传达"这个功能没在工作"，一句"一切正常"传达"它在看着"。

### 8.2 关键错误界面

| 错误 | 界面措辞 | 可用操作 | 🚫 禁止提供 |
|---|---|---|---|
| 沙箱创建失败 | "沙箱没能启动起来" + 诊断信息 | 重试 / 看诊断 / 报告问题 | **"不用沙箱直接运行"** |
| 启动慢（池耗尽） | "启动比平时慢，请稍候…" | 取消 | 跳过隔离 |
| 程序崩溃 | "程序意外退出了"（退出码 + 最后输出） | 查看输出 / 重新运行 | — |
| 内存超限 | "沙箱内存用满了，已停止" | 调整上限 / 重试 | 无限制重试 |
| 外部密钥源不可达 | "暂时拿不到保管在 1Password 里的账号" | 重试 / 改用其他账号 | **"手动输入密钥"**（02 §3.5） |
| 审计写入失败 | "安全档案记不下来了，为安全起见暂停启动新沙箱" | 清理空间 / 调整保留期 | 忽略继续 |
| 缓存校验失败 | "依赖缓存可能被篡改，已拒绝使用" | 重新下载 | 跳过校验 |

**右栏「禁止提供」是本表的重点**。错误界面是安全产品最容易被攻破的地方——用户在受挫时最愿意接受任何让事情继续的选项。这一栏把 02 的两条产品底线固化到了界面层。
